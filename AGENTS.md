# Repository responsibility

This repository is the canonical first-party AV Evidence Toolkit software source.
Keep CLI, schemas, tests, generic methods/templates, documentation, packaging and
CI here. Analytical governance, title-specific conclusions and the analytical
corpus remain in their own repository. Primary media and large evidence runs
remain external. Follow the human's task scope and authorization.

Do not commit credentials, private source filenames/paths, primary media, model
weights, downloaded wheels/binaries, virtual environments, caches or generated
distributions. Generate tiny synthetic fixtures during tests. Preserve MIT source
licensing and third-party notices, including GPL dependency distribution material
when producing optional offline artifacts.

# Evidence and analytical behavior

Preserve source hashes, selected streams, timing/frame indices, transformations,
raw observer responses and historical receipts. Context-minimized Stage 1 and
contextual Stage 2 remain distinct. Later corrections and human review add
records; they do not rewrite original observations or failed probes.

Separate provenance and integrate interpretation at the dramatic-event level.
Do not treat model prose as source fact, dependent agreement as independent
corroboration, soundtrack RMS as emotion or sparse stills as continuous motion.
Localize contradictions to affected premises/dependents and retain alternatives
and `OPEN` where evidence cannot discriminate. A scoped human validation is not
global qualification.

# Development and validation

Preserve the `v1.5.0a2-git-baseline` migration history separately from feature
work. Keep old artifact schemas/semantics readable; document extensions and
explicit migrations. Avoid refactoring unrelated code during feature work.

Use project metadata for dependencies. Standard validation is generated-media,
mock/local and zero paid API cost. Run focused tests for changes, then the full
regression suite before release; report passed, failed and skipped counts.
Use `scripts/scan_public_source.py` before publishing source and distribution
builders for source-bound output receipts. Do not claim a platform or perceptual
capability validated unless it was actually executed/tested.

Normal GitHub Actions must never execute paid observer calls. Preserve the
existing hosted-media authorization, task admission, budget and credential-safe
usage-receipt controls. An unresolved question or a validation plan is not
authorization to upload or spend. Never store API secrets or media base64 in
evidence/configuration journals.
